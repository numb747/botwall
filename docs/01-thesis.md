# 论点

## 采集是一门由单位成本决定毛利的生意

数据采集的技术选型，本质上是成本决策：住宅代理按流量计费，比数据中心 IP 贵一到两个数量级；无头浏览器相对纯 HTTP 请求，在内存、CPU、带宽、并发密度上差出一到两个数量级；打码和模型调用按次计费。一天几百万请求的量级下，单位成本降 20% 就是能写进损益表的数字。

但这个行业目前**靠经验和口口相传做技术选型**——"这个站得上住宅代理"、"这个站得开浏览器"——没有任何可复现的成本口径。没人能回答"如果不上浏览器会怎样"、"上了住宅 IP 到底解决了哪个问题"。

botwall 要提供的就是这个口径。

## 现有工作全都在测模型，没有一个在测成本

2025 年起出现了一批高质量的验证码基准：Open CaptchaWorld（NeurIPS 2025）、Halligan（USENIX Security '25）、MCA-Bench（AAAI）、CAPTCHA-X、CAPTURE、COGNITION。它们做得很好，但回答的是另一个问题。

它们的输出语句是「**GPT-5 在这批图上得 40%**」。这是 AI 研究的问题意识：验证码是评估多模态模型视觉推理能力的一个 task suite。分析单元是**模型**，指标是**准确率**。

而采集方要回答的是「**这个站的数据，每万条采下来要花多少钱，最便宜的路径是哪条**」。分析单元是**防御配置**，指标是**单位成本**。

没有任何现有基准回答后者。准确率 40% 但单次成本 $0.02 的方案，和准确率 95% 但单次成本 $0.0005 的方案，在工程决策里完全不是一回事——而准确率指标看不出这个差别。

## 验证码是失败模式，不是关卡

这是本项目最重要的一个认知，它决定了整个靶场的结构。

在现代站点上，验证码极少作为常规关卡存在。它是**惩罚**：网络层、传输层、协议层、运行时层、行为层中的某一层已经对你产生了怀疑，系统才用一道题来拦你。

**你看到验证码，说明你在前面某一层已经露馅了。**

所以资深做法是回头查是哪一层漏的，而不是去解那道题。而"研究验证码强度"是在研究症状——真正决定成本的，是你在 L1–L5 上的环境保真度。

这也是为什么 botwall 的靶场把验证码放在第六层、默认关闭、且只在前五层累计风险分超阈值时才触发。

## 采集工程的核心手艺，是「能不能不用浏览器」

无头浏览器相对纯 HTTP 的成本差是一到两个数量级。所以采集工程师的真实价值不在"会用 Playwright 加指纹补丁"——那是入门技能——而在**把一个看起来需要浏览器的站降级到不需要浏览器**。

这一跳发生在协议层：请求签名能不能脱离浏览器静态复现。能，你停在阶梯的 L1；不能，你被顶到 L4 甚至 L5。这是整条阶梯上成本差最大的一道分水岭，也是这门手艺真正的考场。

## 入口选择先于技术选择

在讨论"怎么过这道防御"之前，必须先问一个更便宜的问题：**这条路径真的是必需的吗？**

- 这个数据接口真的需要过验证码吗？很多站的验证码只卡在登录和敏感操作，数据接口本身只需要一个有效会话。
- 有没有移动端 API、小程序接口、开放平台、第三方镜像？**移动端和小程序的风控强度通常比 Web 端弱一个档次**，因为防御投入天然不对等。
- 有没有官方的数据出口、批量下载、RSS、sitemap？

硬闯一层防御的成本，经常是换一个入口的几十倍。**绕过验证码往往是最贵最笨的解法。** 一个成熟的成本模型必须把"换入口"也作为阶梯上的一个选项，而不是只在既定入口上比较技术方案。

## 结论

botwall 不是一个验证码基准，是一个**采集成本模型**。

它的输出不是 leaderboard，是**决策表**：给定目标站的防御特征，你该停在成本阶梯的哪一级、为什么、单位成本是多少。

方法是把真实站点上叠加的防御拆成六个可独立开关的层（见 `02-defense-layers.md`），在可复现的靶场上扫描参数空间，测量每一级的成本倍数（见 `03-cost-model.md`）。
