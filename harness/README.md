# Harness（未开始）

这里将来放成本核算与阶梯扫描——**整个项目的主体**。靶场只是它的被测对象。

## 要建的东西

### 1. 计量，而且是强制的

所有成本必须由 harness 记账，不接受攻击实现自报：

| 项 | 记账方式 |
|---|---|
| LLM token | 攻击实现跑在容器内，调用强制走计量代理，token 由代理记录 |
| CPU / 内存 | cgroup |
| 网络字节数 | 容器网络命名空间 |
| 墙钟 | runner |

现有工作普遍是"作者在论文里写我们花了 $X"——不可复现、不可比较。**把计量放在 harness 层强制执行，是本项目的实质技术贡献之一。**

### 2. 攻击实现的容器协议

攻击实现是黑盒容器，语言不限。它只能看到靶场的 HTTP 接口，拿不到 `signing.py`。

约定（待定稿）：

```
输入  环境变量 CL_TARGET / CL_ITEMS_WANTED
输出  stdout 逐行 JSONL，每行一条采到的记录
退出  0 = 完成，非 0 = 放弃
```

harness 用 `app.data.verify_record` 事后校验每条记录的真伪。**这一步不能省**：blind 模式下靶场返回的是 HTTP 200 + 投毒数据，只统计状态码会把投毒响应算成成功，从而高估通过率、低估重试放大系数 `R`，最终低估单位成本。

### 3. 阶梯扫描

对每个 (profile × 攻击实现) 组合跑一轮，输出：

```
C₁₀ₖ = 10000 × R × (c_proxy + c_compute + c_solve + c_account) + A_dev
```

公式各项的定义见 [`../docs/03-cost-model.md`](../docs/03-cost-model.md)。

最值得优先扫描的一个参数：`l3_protocol.salt_mode` 从 `derived` 改到 `runtime`。它把攻击方从成本阶梯 L1 顶到 L3，是整条阶梯上成本差最大的一跳，也是这套模型最容易出结论的地方。

### 4. 排障工时

同一个 profile 分别在 `diagnostic` 和 `blind` 模式下跑（用 `CL_MODE` 环境变量覆盖，不必复制 profile 文件），记录从管线失效到正确归因的工时 `T_diag`。差值就是"归因能力"的货币化价值。

这项数据目前不存在于任何公开研究中。

## 输出形态

**不是 leaderboard，是决策表。** 每一行回答一个工程问题：给定这类防御特征，该停在哪一级、单位成本多少、关键约束是什么。

配一张成本–通过率的帕累托前沿图，横轴 `C₁₀ₖ`、纵轴成功率，并标出人工打码的价格地板线（约 $0.0005/次）。任何自动化方案如果单次成本高于这条线，它在经济上就没有存在理由。
